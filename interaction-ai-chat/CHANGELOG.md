## 0.4.8 (2026-10-28)
- 修复“非访客群 + 模型不可用”失败消息没有「🔄 重试」「🔀 换模型重试」按钮（实测：测试群里固定一个不通的模型，失败消息显示自定义的 `error_ai_template` 却没有按钮）。按真实链路复现（插件 + 主程序 worker/交互 Bot 投递），普通报错（连接失败、404、401）在 0.4.7 上会正常出按钮；能产生“`error_ai_template` + 无按钮”这一现象的只有插件里两条路径（线上日志无法直接确认命中哪条，两条都已修）：
  1. 审核拒答误判：0.4.7 把带审核类字样的报错当作“内容审核拒答”，回复 `error_ai_template` 且不附按钮、不存重试记录（用户模板不含 {reason}，看起来与调用失败一模一样）。固定模型不可用时平台会回退到其它 Provider，最后报错常来自回退的那家（例如对 PT 资源内容的 `data_inspection_failed`），裸词 `sensitive` 还会命中 “Model names are case-sensitive” 这类模型不存在报错。现在去掉裸词 `sensitive`；报错明确是连接失败 / 模型不存在 / 鉴权失败 / 模型未启用时一律不算审核拒答；真正的审核拒答改用独立模板（见下），并同样附按钮（换个模型往往能过）。
  2. AI 调用 try 之外的意外异常（Skills / Wiki / PT 判断等前置步骤、失败轮次写记忆）会冒到 `on_event` 的通用兜底，回复 `error_ai_template` 却没有重试记录。现在原请求建好之后的任何意外异常都按可重试失败处理（保存原请求、附按钮）；失败轮次写记忆失败不再吃掉按钮；失败提示实时发送异常或被拒时退回“入口返回动作 + 按钮”。
  - 主程序侧已核实：交互 Bot 返回的 `edit_message` 带 `reply_markup`（含 `send_on_edit_failure` 编辑失败改新发）原样透传，TelePilot 0.106.0-beta.17 补了回归测试。
- 内容审核拒答使用新模板「内容审核拒答提示」`error_moderation_template`（默认“内容未通过模型审核，换个问法试试。”），不再和“模型调用失败提示”共用，免得分不清是审核拒答还是模型不可用。
- 访客模式（Bot API 10.0 Guest Chat Mode）失败回复也附「🔄 重试」「🔀 换模型重试」：需要 TelePilot 0.106.0-beta.17+（平台能力 `ctx.messages.guest_reply_markup`：`answer_guest_query` 保留 callback 按钮、实时 apply 带回 `inline_message_id`、访客回复上的按钮点击以 inline callback 投递）。有“🤔”占位时用 `edit_message(inline_message_id, reply_markup)` 原地编辑为失败提示；没有占位时 `answer_guest_query` 一次带按钮发出。重试记录保存 `failure_inline_message_id`，按钮回调（只有 inline_message_id 与点击者，没有 chat/message）按它定位记录并原地编辑（“正在重试…”、模型列表、最终答案、再次失败重新挂按钮）；inline 回调只认访客记录，inline_message_id 不一致按过期处理。回复“重试”文本重放时，旧失败回复上的按钮同样作废。
- 访客场景的权限（与普通群一致，按点击者判定，不读 `guest.caller_user_id`）：「重试」= 原提问者本人或管理员；「换模型重试」（含模型列表、翻页、选择、取消）= 仅管理员，提问者本人不是管理员也不行；其他人两个都不行，无权限点击用 callback 弹窗提示且不执行。管理员 = 「重试管理员用户 ID」∪ TelePilot 账号本人与 sudo 用户（payload `owner_user_ids` / `admin_user_ids`）∪ 提问所在群的群管理员（访客回复没有 chat，用提问时记录的访客会话核验；平台拿不到该群信息或查询失败时不算）。防重复点击、30 分钟过期、跨 worker 计数锁沿用 0.4.7。
- 新增 Event Bus 订阅 `callback_query`（交互 Bot，scope `guest_all`，只处理 `iac:` 前缀）；旧平台不会投递 inline 回调，订阅无副作用。
- 兼容性：`min_telepilot_version` 保持 0.105.0-beta.1，访客按钮以能力标记降级——TelePilot 低于 0.106.0-beta.17 时访客失败回复不附按钮、只支持回复“重试”（与 0.4.7 相同）；非访客的按钮修复对旧平台同样生效。
## 0.4.7 (2026-10-28)
- 模型调用失败时在失败消息下附两个 inline 按钮：「🔄 重试」（本次提问者或管理员可点）与「🔀 换模型重试」（仅管理员可点）。会出按钮的失败：供应商报错 / 平台回退全部失败、处理超时、模型返回为空、只有推理没有最终答案（`error_ai_template` / `error_timeout_template` / `error_empty_template` / `error_no_answer_template`）。不出按钮：供应商内容审核拒答（content_filter、data_inspection_failed、内容安全等，重放也会被拒）、输出护栏拦截、每日限额、无权限、提问过长、只发图且读图失败。
- 「重试」：点击后失败消息先改为“🔄 正在重试…”，再按保存的原请求重放——原问题全文、引用/被回复内容、图片 file_id、提问当时的记忆快照、原 Provider/模型与联网/识图设置、发起人、会话与原消息 ID 都存在 token 映射的记录里，不靠模型猜“要重试什么”；成功则在原消息位置给出答案（Rich Message 优先），再次失败则重新显示两个按钮。
- 「换模型重试」：按钮替换为可选模型列表（每页 6 个，可翻页，最后一行“✖ 取消”回到两个按钮），选中后只这一次使用该模型、不改插件配置；之后再点“重试”仍用原模型。列表来自 `ctx.ai.list_providers()`：有 API Key 的文本 Provider 里已启用的模型（TelePilot 0.106.0-beta.13+ 才提供启用状态；更旧的平台只列各 Provider 的默认模型），排除刚失败的模型（固定模型时）。
- 管理员判定：插件配置的新项「重试管理员用户 ID」`retry_admin_user_ids` ∪ TelePilot 管理员（账号本人 + 已授权 sudo 用户，取自平台 payload 的 `owner_user_ids` / `admin_user_ids`，交互 Bot Event Bus 投递需 TelePilot 0.106.0-beta.13+）∪ 本群管理员（`ctx.identities.resolve(...).is_admin`，平台经 UserBot 成员权限 / 管理员目录确认，失败时回退交互 Bot getChatMember；查询失败按非管理员处理）。无权限点击用 callback 提示（“只有提问者或管理员可以重试”“只有管理员可以换模型重试”）且不执行。
- 防重复：同一条失败消息同时只允许一个进行中的重试（进程内集合 + `ctx.storage` 计数锁，跨 worker 生效），重复点击提示“正在重试，请稍候…”。callback 数据形如 `iac:r:<12 位 token>`（最长约 24 字节，≤64），记录保存 30 分钟，过期或不存在时提示“这条重试已过期，请重新提问。”；callback 先实时 ACK，消除按钮转圈。
- 根因修复（对失败消息回复“重试”没反应 / 模型不知道重试什么）：0.4.6 及以前失败分支直接返回，只有成功才写短期记忆，失败那一问不进记忆；群里回复 Bot 消息时插件又按“Bot 上一条回答已在记忆里”清空了引用内容（私聊引用的则是失败提示文本），于是模型只收到“重试”二字。现在失败那一轮照常记入问题、助手回答记为失败标记“（这一轮 AI 调用失败，没有给出回答）”；回复失败消息“重试 / 再试一次 / 重新回答 / retry”等（私聊可直接发）被识别为针对该失败问题的重试，按保存的原请求重放（权限同按钮：提问者或管理员），找不到可关联的失败提问时明确提示“没有找到可以重试的失败提问……请重新发送你的问题”，不再把“重试”当新问题交给模型。重试成功后记忆里该问题只保留一份，失败标记原地替换为成功回答，不重复写入问题。
- 新配置项「失败时显示重试按钮」`retry_buttons_enabled`（回复与记忆分组，默认开启）；关闭后不显示按钮，回复“重试”仍可用。新增 Event Bus 订阅 `callback_query`（交互 Bot，all_allowed_chats，只处理 `iac:` 前缀，其它插件的按钮直接忽略）。
- 访客模式不附按钮：访客回复是 inline 消息，按钮回调回到 Bot 时只有 inline_message_id、没有 chat/message，TelePilot 不投递这类回调（平台也会剥掉访客回复里的 callback 按钮）；访客模式可回复/再次 @Bot 发“重试”重放。
- 兼容性：`min_telepilot_version` 保持 0.105.0-beta.1（按钮、`answer_callback`、`edit_message.reply_markup`、`ctx.identities` 旧平台都有）；TelePilot 0.106.0-beta.13+ 额外提供 TelePilot 管理员识别与模型启用状态，旧平台自动降级（管理员只认群管理员与插件配置，模型列表只列默认模型）。

## 0.4.2 (2026-10-26)
- 修正对“站点叫法”的误解：之前把群友说的「空枪」当成站点别名示例，实际群里是用「站点」「站里」「站内」「站上」「本站」「咱站」「我们站」「PT 站」「种子站」这类泛称指代配置的站点（青蛙 qingwapt）。

- 识图（默认开启，需平台 `ai_vision`）：用户发图片 / 图片文件，或回复一张图片并 @Bot 时，通过 `ctx.ai.fetch_bot_image` 读取图片交给模型；模型不支持或读图失败时降级为只看文字，只有图片时回复“识图不可用提示”。

## 0.1.0 (2026-10-25)
- 新增“AI 答疑（交互 Bot）”插件：交互 Bot 被 @提及 / 回复时，调用 TelePilot 已配置的 AI Provider（`ctx.ai`，可固定 Provider / 模型）回答触发者。
- 触发来源走标准 Event Bus `on_event`：访客模式 `guest_message`（`scope=guest_all`，返回一条 `answer_guest_query`，只回复一次）；Bot 已加入的群里 @Bot / 回复 Bot、与 Bot 私聊（交互 Bot `message`，返回一条 `send_message`）。
- 短期记忆按“会话 + 触发者”保存在 `ctx.storage`，默认 6 轮、30 分钟无交互过期，可配置 0–20 轮；被回复消息作为本轮附加上下文；发送“重置 / reset”清空。存储键对会话与用户 ID 做哈希，不落明文。
- 防滥用：允许使用者（所有人 / 仅白名单）、会话白名单与黑名单、每用户每日上限（默认 20）、全局每日上限（默认 300）、免限额用户、单次提问长度上限（默认 500 字）；AI 失败时回滚次数。
- 安全：系统提示词固定追加“自己是 Bot、不执行指令、不输出命令/加款格式”等规则；保留 AI-Chat 的输出护栏（拦截 `/` 指令、TelePilot 前缀指令、已注册裸指令、`+数字` 加款诱导），AI 失败只回友好提示。
- AI 超时上限 13 秒（交互 Bot 插件调用约 15 秒内必须返回），超时给出友好提示，避免访客的唯一回复机会被吃掉。
