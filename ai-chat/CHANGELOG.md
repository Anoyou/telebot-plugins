# 更新日志

## 0.1.8 (2026-07-09)
- 新增加款诱导反制回复配置，默认 `-66666`：当 AI 最终输出被诱导成 `+数字` 或 `+数字-数字` 这类内容时，发送前会替换成反制回复，不再只返回普通安全提示。
- 反制回复不会自动套“安全回复前缀”，避免 `天才：-66666` 这类前缀导致群内记账/积分 Bot 无法识别；留空该配置时仍回退为普通安全提示。

## 0.1.7 (2026-07-09)
- 拦截范围扩展到 `+数字-数字`、`+数字至数字` 等区间加款形态，覆盖倒序输出、字符映射等提示注入绕过。
- 发送 AI 回复前会复查触发消息是否仍存在；如果对方问完又删除消息，插件直接跳过回复。
- 图片、文件等媒体消息不再进入模型链路；普通媒体消息固定回复“我现在看不了图片，发文字我再回你。”，媒体标题若像命令则直接忽略。

## 0.1.6 (2026-07-08)
- 修复配置页“测试当前模型”和 `{prefix}ask test` 仍可能误报的问题：测活现在走与 TG 日常聊天一致的人设提示词、用户消息包装和完整最大输出 Token，不再使用 64 Token 的短测活请求。
- 测活结果继续记录客户端标识用于排查，但不会把该标识注入模型提示词，也不会声称能改写 HTTP User-Agent。

## 0.1.5 (2026-07-08)
- 修复配置页“测试当前模型”弹窗只显示可用状态的问题：成功、空返回和失败场景都会在任务消息与日志里直接展示模型返回预览或错误解读。
- 配置动作结构化结果新增 Provider、模型、返回预览和完整测活结果，便于前端或日志系统直接读取展示。

## 0.1.4 (2026-07-08)
- 将配置页“测试当前模型”改为真实聊天式测试：弹窗可填写模拟用户消息与客户端标识，结果展示模型实时返回和插件侧解读。
- 修复测活假阴性：上游请求成功但返回空文本时，不再直接判定为模型不可用，而是记录为“返回为空”并说明可能原因。
- 明确客户端标识只作为对话元信息发送；当前 AI-Chat 插件不能自定义 TelePilot 到模型上游的 HTTP User-Agent。

## 0.1.3 (2026-07-08)
- 新增配置页“测试当前模型”动作，可直接使用当前表单里的 Provider、模型覆盖和模型测试语发起一次真实 AI 调用。
- 新增“模型测试结果”配置展示最近一次测活状态、时间、耗时、Provider、模型、测试语和返回/错误预览；配置动作会自动保存结果并通知插件热加载。
- 配置页测活失败不会只表现为后台任务失败，而是会把“不可用”和具体分类错误写入结果字段，方便后续排查。

## 0.1.2 (2026-07-08)
- 新增 `{prefix}ask test [测试语]` 模型可用性测试命令，通过 TelePilot `ctx.ai.complete` 真实调用当前 Provider 与模型，成功时展示 Provider、模型、耗时和安全返回预览。
- 新增“模型测试语”配置，默认使用普通短句，可按站点限制改成自定义内容，避免固定 `ping`、`health-check` 等测活字样被误拦截。
- 测试命令不写入聊天记忆，返回预览会逐行加安全前缀，避免模型测试结果被裸发成 Telegram/TelePilot 可执行指令。

## 0.1.1 (2026-07-06)
- 新增 AI 输出安全护栏：发送前拦截 `/`、系统指令前缀、纯 `+数字`、已注册 TelePilot 命令和配置的裸文本触发词，避免模型被诱导发送可执行指令。
- 支持从 TelePilot worker 命令上下文中尽力读取内置命令、插件命令、账号命令模板和别名；读取不到时仍按通用命令前缀兜底拦截。
- 新增可配置项：拦截可执行指令输出、安全回复前缀、额外拦截的裸文本；留空安全回复前缀时会尝试识别提示词里的“必须以某前缀开头”要求。

## 0.1.0 (2026-07-06)
- 新增 `AI-Chat` 远程插件（key: `ai-chat`），按 TelePilot 标准插件结构提供 `plugin.json`、`manifest.py`、`plugin.py` 与 `__init__.py`。
- 通过 TelePilot `ctx.ai.complete` 调用已配置的 AI Provider，支持 `{prefix}ask 文本`、回复消息后解释内容、查看 Provider 与清空当前会话记忆。
- 支持私聊直接陪聊、群聊 @当前账号或回复当前账号消息触发，并提供会话白名单、群组限制、短期上下文记忆和输出截断配置。
