# 更新日志

## 1.1.18 (2026-10-29)
- 入口 `start_paid_game` 增加 `entry_policy`（按群会话、有奖金），并在 `ui.rule_editor` 里声明规则编辑器的启动词提示与说明。TelePilot 0.111.0-beta.2+ 按声明处理、不再查宿主兜底表；结果与原来完全相同。旧宿主忽略这两个字段。游戏与派奖逻辑无变化。

## 1.1.17 (2026-10-29)
- 触发指令名补输入提示，配置由 TelePilot 通用表单渲染（旧专属页 0.110.0-beta.2 起只作对照）。

## 1.1.16 (2026-10-28)
- 兼容性：`min_telepilot_version` 提高到 `0.72.0-beta.2`。`manifest.py` 向 `Manifest` 传入了 `requires_platform_capabilities`，该参数 TelePilot 0.72.0 起才支持，更早的版本导入插件时直接报 `TypeError`（宿主兼容性检查在 0.59.1 / 0.71.3 上实测）；提高后旧版本会在加载前给出“请先更新 TelePilot”的明确提示。功能无变化。
- `manifest.py` 的配置使用说明（`x-usage-guide`）与 `plugin.json` 不一致，统一为 `plugin.json` 的文案。

## 1.1.15 (2026-10-26)
- 配置表单：触发指令名（`command`）、答题限时（秒）（`timeout`）已有默认值，从 `required` 中移除，不再被 App 标成「必填」；留空或不填时运行时仍按默认值处理，不改变任何业务逻辑。

## 1.1.14 (2026-08-15)
- 新增标准 Event Bus 主入口；题面编辑和奖励结算改走 MessageOps，删除文本发奖兜底并保持失败关闭。

## 1.1.13 (2026-08-15)
- 补充 TelePilot 0.97.0 平台能力声明，并同步 plugin.json 与 manifest.py。


## 1.1.12 (2026-07-30)
- 显式声明 `payout` 高风险权限并开启资金动作严格 Trace，兼容最新 TelePilot 插件开发指南与运行时权限校验。

## 1.1.11 (2026-07-25)
- 修复无活跃游戏的群消息仍会回查 Telegram 发送者、网络回查超时后连续触发插件熔断的问题；现在先检查当前聊天是否存在活跃 24 点局，再解析答题者信息。

## 1.1.10 (2026-07-12)
- 答题结算改由 TelePilot `ctx.messages` 受控接口读取平台保存的题面消息 ID，installed 模式下可继续编辑原题面。

## 1.1.9 (2026-07-10)
- 按最新插件开发指南对齐：`on_interaction` 主路径改用标准事件信封（`event_from_interaction_payload`）读取事件类型、聊天/消息 ID、答题文本和赢家 actor，旧平铺 payload helper 保留为兜底。
- 元数据同步：补充 `min_telepilot_version="0.33.0"`（plugin.json 与 manifest 一致），递增 patch 版本到 1.1.9。
- 保持原有 24 点游戏规则、命令行为、文案语义与超时逻辑不变。

## 1.1.8 (2026-07-06)
- 答对后编辑原题面时不再重复追加奖金行，保留开局题面里的奖金展示；发奖仍保持 `payout` action 链路。

## 1.1.7 (2026-07-06)
- 开局题面标题按“名称 + 版本号 + 开始”格式展示，便于远程实测确认当前 worker 实际加载的插件版本。

## 1.1.6 (2026-07-05)
- 开局题面标题追加插件版本号，便于远程实测确认当前 worker 实际加载的插件版本。

## 1.1.5 (2026-07-05)
- 交互 Bot 开局题面保存消息 ID，答对后优先编辑原题面追加答对者和答案，不再额外发送“答对了”公告。
- 发奖仍保持原 `payout` action 链路，`result` / `settlement` 结算元数据不变。

## 1.1.4 (2026-07-05)
- 答对公告移除发奖状态承诺文案；实际发奖仍继续返回 `payout` action 交给 TelePilot 执行。

## 1.1.3 (2026-07-05)
- 修复 24 点表达式校验在 Python 3.9 测试环境下使用 `int | float` 作为 `isinstance` 参数导致合同测试失败的问题。

## 1.1.2 (2026-07-05)
- 交互答对后的 `payout` action 增加玩家 user id 兜底，提升 userbot 发奖定位稳定性。
- userbot 命令开局答对后的奖励改走 TelePilot 标准 `payout` 链路，避免插件直接发奖绕过平台动作记录。

## 1.1.1 (2026-07-04)
