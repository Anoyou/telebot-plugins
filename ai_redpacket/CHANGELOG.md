# 更新日志

## 0.1.16（2026-07-15）

- `{date}`、`{daily_limit}`、`{retry_count}`、`{prefix}`、`{command}` 改为所有消息模板均可使用的通用占位符，结算模板使用 `{date}` 时不再因缺少字段而整段回退默认文案。
- 配置页按“通用占位符”和各消息的场景占位符重新说明可用字段；未知或拼错的占位符仍执行安全回退，不会静默显示为空白。

## 0.1.15（2026-07-15）

- 移除每条答对结果末尾自动追加的补发说明，成功消息现在只展示管理员配置的模板内容；“申请补发奖励”按钮继续保留。

## 0.1.14（2026-07-15）

- 找不到近期发言时，补发提示改为优先显示答题者姓名并截断到 10 个字符，不再直接展示 Telegram User ID；提示文案同步简化为先在群里任意发言一次后重试。
- 补发提示中的 `/airp list` 改为可点击复制的代码文本，方便找不到原答题结果的用户重新打开补发入口；最低 TelePilot 版本调整为 0.60.2。

## 0.1.13（2026-07-14）

- 新增群员公开只读命令 `/airp list`，仅允许自助查询进行中红包和使用补发入口；管理员原有系统前缀命令及权限保持不变。
- 补发按钮统一显示为“日期-雨露均沾 · 申请补发奖励”；点击时先查询本人以个人账号在本群发送的近期消息，找不到时仅弹窗提示先发言，不提交发奖动作；找到后回执会明确补发金额及 UserBot 的后续回复形式。
- 列表中的开题链接改为“点击此处跳转，领取今日份雨露均沾”，并在红包 ID 下展示“红包开头：今日份雨露均沾 - 第 YYYY-MM-DD 期”。
- 答错后的新答案按钮增加 2 秒服务端冷却；冷却期内连点只弹窗提示，不增加答题次数，也不消耗第二次机会。
- 红包实际有效期取配置时长与创建日次日 08:30 中较早者；升级后仍在进行的旧红包也会自动缩短到该截止时间，但不会被延长。
- 每日 08:00 按群汇总提醒仍未领完的前一日红包，附领取进度和开题消息链接；提醒使用持久化记录与消息投递键双重去重，08:30 后沿用现有自动结算流程，并提供提醒消息模板、占位符和预览配置。

## 0.1.12（2026-07-14）

- 答对结果新增“申请补发奖励”按钮；用户先在群里发言后可申请重新核验，平台复用原 `payout_key` 判断是否已经发放，未发放才补发，已发放不会重复派奖。
- 补发按钮仅允许原答题者操作，并在申请前校验答题记录、领取归属与成功状态；补发不会再次扣减红包余额。
- 答对和挑战失败结果固定显示答题者姓名；答对结果、使用说明和找不到近期发言的提示中补充补发操作说明。
- 修复同一用户反复点击领取入口时重复发送同一道预约题的问题；已有进行中题目时只弹窗提示回到原题，不再产生重复题面。
- `{prefix}airp list` 改为只显示进行中的红包，并展示已领取题数、已领取金额和开题消息链接；原命令自动删除，列表回执保留。
- 进行中红包列表新增按红包区分的公共补发入口，便于旧版答对但因没有近期发言而未到账的用户在发言后自助申请补发。

## 0.1.11（2026-07-14）

- 单人和全员重置结果改由交互 Bot 发送，成功响应 3 秒后自动删除；原管理员命令仍在操作成功后自动删除。
- 每道题按“题目预约时间（秒）”的实际配置计时；超时未提交时原题面会更新为“本题失效并已回归题库”，不消耗领取与答题次数，并在 5 秒后自动删除。
- 答错后允许重试时会按实际预约时间重新计时；提交答案与超时回收通过事务和提交 token 原子判定，避免临界时刻重复处理。
- 结算名单和周榜改为优先显示 Telegram 姓名，姓名为空时才回退到 `@用户名`，展示长度仍最多 10 个字符。

## 0.1.10（2026-07-14）

- 新增管理员命令 `{prefix}airp reset all`，以统一的新统计起点重置当前账号下当日所有参与者的领取与答题次数限制；既有奖励、红包扣款和答题历史保持不变。
- 默认或自定义创建红包、重置单人/全员次数、成功关闭红包后会自动删除原管理员命令消息；参数错误或操作失败时保留命令，便于查看失败原因。

## 0.1.9（2026-07-14）

- 题库生成改为优先单次生成最多 200 题，默认允许请求 65536 输出 token，并可在配置页调整到 4096-131072；超过 200 题或模型未一次输完时才继续补齐。
- AI 输出改用每行一题的 JSONL；即使最后一行因模型输出上限被截断，前面已完成的题目仍可校验、保存并在后续仅补齐缺口。
- 单批输入同样遵守 12 万字符上限；超长网页按首段、中段和尾段抽样，避免一次请求吞入完整 30 万字符正文。

## 0.1.8（2026-07-14）

- 题库、网页缓存、红包与答题记录改存 TelePilot `ctx.data_dir` 持久化目录，插件更新不再删除运行数据；首次加载会自动迁移旧目录中的 SQLite。

## 0.1.7（2026-07-14）

- 题库生成支持中断、终止和继续：每个成功批次立即保存阶段性题库，中断、Provider 失败或服务重启后不再丢失已生成题目。
- 再次生成会复用缓存正文和阶段性题库，并读取配置页当前选择的 Provider 与模型，支持切换模型后继续补齐。
- 支持流式接收 AI 输出，并在任务窗口节流展示当前批次已接收字符数；不支持流式的 Provider 自动回退普通生成。
- AI 调用异常纳入有限重试；批次失败时记录具体错误摘要并自动降低后续并发，减少限流和超时造成的连续失败。
- 新增“自动置顶红包入口”配置，默认由交互 Bot 置顶带领取按钮的红包消息，避免群聊后续发言淹没入口。
- 红包开场提供“领取我的雨露”按钮，每道题和答题结果提供“我也要雨露均沾”按钮，所有群成员可随时加入；题面会以“@用户名 这是你的专属雨露”标记归属，答案按钮继续严格绑定本人。
- 最低 TelePilot 版本调整为 0.59.0，以使用后台配置任务中断与终止控制。

## 0.1.6（2026-07-14）

- 补全插件中心使用说明：明确列出默认创建、自定义创建、题库列表、红包列表、关闭、重置、帮助和周榜命令；运行时帮助统一通过 TelePilot `current_command_prefix()` 展示系统实际前缀。
- 默认题库改为动态选择框；生成或补齐题库后自动回填题库标题、题数和 ID 选项，已有默认题库 ID 保持兼容。
- 显式创建红包时，若配置的单题金额上下限与“总金额 / 份数”冲突，插件会按命令参数自动收缩有效边界，继续保证整数、随机分配、总额守恒和非平均分配。
- AI 出题系统提示词通过浅色占位内容展示内置要求，留空仍使用插件内置提示词。
- 新增红包结算与每周榜单消息模板；预览区补齐红包开场、答题题面、答对结果、挑战失败、红包结算和每周榜单六类消息。
- 最低 TelePilot 版本调整为 0.58.2，以使用动态选择框、独立浅色占位内容和完整消息模板预览能力。

## 0.1.5（2026-07-14）

- 挑战失败的题面在展示结果 60 秒后由交互 Bot 自动删除，插件禁用或热重载时由平台统一清理尚未执行的删除任务。
- 红包全部领完或到期后自动发布一次结算消息；运气王、倒霉蛋显示在折叠名单上方，领取名单按金额降序排列，展示名最多保留 10 个字符。
- 新增管理员命令 `{prefix}airp-7`，手动查询当前周榜；分别展示答对次数前 5 名和累计奖金前 5 名，榜单默认折叠。
- 周榜周期调整为每周日 10:00 至下周日 10:00；默认在每周日 10:00 自动向周期内有成功领取记录的群发布上一完整周期榜单，并通过数据库标记避免重复发榜。
- 数据库升级到 v4，新增展示名、红包结算状态和周榜发布幂等记录；显式声明 `delete_message`、`payout` 权限，并新增“每周日自动发布周榜”配置开关。

## 0.1.4（2026-07-14）

- 配置页按基础设置、题库来源、AI 生成、AI 出题要求、红包与答题分组；短配置项使用双列布局，URL、状态和长提示词独占整行。
- 题库分批生成由串行改为可配置并发，默认同时生成 3 批、范围 1-5；保留小批 JSON 校验与失败重试，Provider 限流时可手动降低并发。
- 题库生成进度详情改用中文字段：`批次`、`目标题数`、`已生成题数`，不再显示 `batch`、`target`、`generated`。
- 新增管理员 `reset [用户ID]` 命令，通过记录新的当日统计起点重置领取与答题限制，不删除既有奖励、红包扣款和审计记录。
- 单独发送管理指令会按默认配置创建红包；新增默认总金额配置，默认奖池 150000、40 份、使用默认题库，并将新安装默认单题上限调整为 10000 以容纳该奖池。

## 0.1.3（2026-07-14）

- 题库目标题数调整为 100-500，默认 200；已有题库不足目标数量时保留原题并继续分批补齐，达到目标后才直接返回现有状态。
- 新增按账号和来源 URL 保存的网页正文缓存；首次抓取后，AI 失败重试和后续题库扩容直接复用缓存，不再重复请求网页。
- 每日成功领取上限改为可配置的 1-100 次，答错后重试次数改为可配置的 0-10 次，并同步更新并发领取校验和动态提示文案。
- 配置页开放“默认题库”字段，生成或补齐后自动写入当前题库 ID；创建红包未指定题库时优先使用该配置，不再要求先执行题库列表命令。
- `{daily_limit}` 和 `{retry_count}` 作为通用模板占位符注入红包开场、答题题面、答对结果与失败结果模板。
- 他人点击不属于自己的答题按钮时返回“点点点，不是你的题你也点！”弹窗，服务端继续按答题记录所有者校验，且不改变原用户答题状态或红包余额。
- 新增 `{date}` 通用模板占位符，按配置时区输出 `YYYY-MM-DD`；默认红包开场模板会自动展示今日日期。

## 0.1.2（2026-07-14）

- 题库首次生成改为单次按钮触发、内部自动分批调用 AI，每批限制输出规模，避免一次生成大量题目时返回超长或损坏 JSON。
- 每批 AI 结果都会进行严格 JSON 与题目结构校验，格式损坏时自动重试；所有批次完成后才一次性保存，失败时不会留下不完整题库。
- 配置动作日志新增分批重试和已生成题数进度，方便直接判断网页抓取、AI 调用与题库保存分别进行到哪一步。

## 0.1.1（2026-07-14）

- 题库生成主入口迁移到插件配置页，新增“生成题库（仅首次）”按钮；题库生成成功后再次点击只返回现有状态，不再抓取网页或调用 AI。
- 新增 TelePilot Provider 和模型下拉选择；未选择时使用自动路由，选择后固定调用指定 Provider/模型，不再强制要求 `long_context` 标签。
- 将“每次生成题目数”改为“题库题目总数（仅首次生成）”，将“默认红包题目数”改为“默认红包份数（每份一题）”，并补充每位用户只回答一道题的说明。
- Telegram 管理命令不再承担题库生成，只保留题库状态查询、红包创建、列表和关闭能力。

## 0.1.0（2026-07-13）

- 新增独立 `ai_redpacket` 插件，通过 TelePilot HTTP facade 抓取配置 URL，并调用平台 AI Provider 生成三选一题库。
- 新增插件内 SQLite 题库、红包、红包题目和用户答题记录，使用 WAL、事务和唯一索引保证并发领取与重复提交安全。
- 新增管理员题库更新、题库列表、红包创建、红包列表和红包关闭指令。
- 新增 Interaction Bot 领取与三选一答题流程：首次答错允许重试一次，第二次答错结束当日挑战。
- 新增每日最多成功领取一次限制，默认按 `Asia/Shanghai` 自然日计算。
- 新增整数红包随机分配，保证单题金额在上下限内、总额严格守恒，并拒绝无法避免平均分配的参数组合。
- 答对后返回带稳定 `payout_key` 的平台 `payout` 动作，由 UserBot 发放并复用 TelePilot 的幂等与失败补偿能力。
- 题库刷新保留进行中红包引用的旧题目，红包关闭或过期后拒绝继续结算；答题提交同时绑定账号、聊天、红包、用户和随机 token。
- 新增红包、题面、答对和挑战失败消息模板及占位符说明，配置页可直接预览 Telegram HTML 效果。
