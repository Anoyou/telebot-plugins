# 更新日志

## 0.1.3（2026-07-14）

- 题库目标题数调整为 100-500，默认 200；已有题库不足目标数量时保留原题并继续分批补齐，达到目标后才直接返回现有状态。
- 新增按账号和来源 URL 保存的网页正文缓存；首次抓取后，AI 失败重试和后续题库扩容直接复用缓存，不再重复请求网页。
- 每日成功领取上限改为可配置的 1-100 次，答错后重试次数改为可配置的 0-10 次，并同步更新并发领取校验和动态提示文案。
- 配置页开放“默认题库”字段，生成或补齐后自动写入当前题库 ID；创建红包未指定题库时优先使用该配置，不再要求先执行题库列表命令。
- `{daily_limit}` 和 `{retry_count}` 作为通用模板占位符注入红包开场、答题题面、答对结果与失败结果模板。
- 他人点击不属于自己的答题按钮时返回“点点点，不是你的题你也点！”弹窗，服务端继续按答题记录所有者校验，且不改变原用户答题状态或红包余额。
- 新增 `{date}` 通用模板占位符，按配置时区输出 `YYYY-MM-DD`；默认红包开场模板会自动展示今日日期。

## 0.1.2（2026-07-14）

- 题库首次生成改为单次按钮触发、内部自动分批调用 AI，每批限制输出规模，避免一次生成大量题目时返回超长或损坏 JSON。
- 每批 AI 结果都会进行严格 JSON 与题目结构校验，格式损坏时自动重试；所有批次完成后才一次性保存，失败时不会留下不完整题库。
- 配置动作日志新增分批重试和已生成题数进度，方便直接判断网页抓取、AI 调用与题库保存分别进行到哪一步。

## 0.1.1（2026-07-14）

- 题库生成主入口迁移到插件配置页，新增“生成题库（仅首次）”按钮；题库生成成功后再次点击只返回现有状态，不再抓取网页或调用 AI。
- 新增 TelePilot Provider 和模型下拉选择；未选择时使用自动路由，选择后固定调用指定 Provider/模型，不再强制要求 `long_context` 标签。
- 将“每次生成题目数”改为“题库题目总数（仅首次生成）”，将“默认红包题目数”改为“默认红包份数（每份一题）”，并补充每位用户只回答一道题的说明。
- Telegram 管理命令不再承担题库生成，只保留题库状态查询、红包创建、列表和关闭能力。

## 0.1.0（2026-07-13）

- 新增独立 `ai_redpacket` 插件，通过 TelePilot HTTP facade 抓取配置 URL，并调用平台 AI Provider 生成三选一题库。
- 新增插件内 SQLite 题库、红包、红包题目和用户答题记录，使用 WAL、事务和唯一索引保证并发领取与重复提交安全。
- 新增管理员题库更新、题库列表、红包创建、红包列表和红包关闭指令。
- 新增 Interaction Bot 领取与三选一答题流程：首次答错允许重试一次，第二次答错结束当日挑战。
- 新增每日最多成功领取一次限制，默认按 `Asia/Shanghai` 自然日计算。
- 新增整数红包随机分配，保证单题金额在上下限内、总额严格守恒，并拒绝无法避免平均分配的参数组合。
- 答对后返回带稳定 `payout_key` 的平台 `payout` 动作，由 UserBot 发放并复用 TelePilot 的幂等与失败补偿能力。
- 题库刷新保留进行中红包引用的旧题目，红包关闭或过期后拒绝继续结算；答题提交同时绑定账号、聊天、红包、用户和随机 token。
- 新增红包、题面、答对和挑战失败消息模板及占位符说明，配置页可直接预览 Telegram HTML 效果。
