# 更新日志

## 0.1.28（2026-07-20）

- 姓名与排行榜公开展示改为复用 TelePilot 0.70.9 的统一姓名清洗能力，过滤 Unicode 控制符、零宽字符、不可见空白和填充字符，并保持最多 10 个字符。

## 0.1.27（2026-07-19）

- 修复普通成员因 UserBot 本地实体缓存未命中而显示为“匿名用户”的问题：依赖 TelePilot 0.70.6 按 user_id 重新解析 UserBot 实体并重试权限核验。
- 保持匿名管理员安全边界：只有 UserBot 明确确认 `anonymous=true` 时才使用管理员标签，实体重试不会把匿名管理员真实姓名带入群消息。
- 每次按钮回调只核验一次身份并复用公开姓名；仍无法核验时写入脱敏运行日志，并提示用户先在群内发言后重试，不再把未知身份写成“匿名用户”继续参与。
- 增加新红包题目批次隔离回归测试，确认每次创建红包都会从当前题库重新随机抽取题目，不会复用上一红包的题目槽位。
- 清理 Manifest 中误声明的 `payout` 权限；继续保留结果动作里的 `payout`，消除 Worker 启动时的未知权限警告且不影响发奖。

## 0.1.26（2026-07-19）

- 匿名管理员点击领取、答题或申请补发时会被直接拒绝，并收到仅自己可见的提示；不会创建题目、消耗次数或触发发奖。
- 非匿名管理员和普通成员保持原有参与流程，不受本次限制影响。

## 0.1.25（2026-07-18）

- 红包开场、答题题面、答对与失败结果、到期提醒、每日结算和周榜全面迁移到 Telegram Rich Message，使用标题、段落、列表和折叠详情呈现。
- Rich Message 发送与编辑完整保留领取、A/B/C 答题、补发入口等 Inline 按钮，以及回复、置顶和消息 ID 保存语义；回调确认、参数错误和管理提示仍使用普通消息。
- 兼容升级前已保存的自定义 Telegram HTML 模板：仅内置旧默认模板自动迁移为 Rich HTML，自定义模板继续按普通 HTML 发送和编辑，避免排版变化。

## 0.1.24（2026-07-18）

- 答题结果和题目超时消息改用 TelePilot 官方 Rich Message 编辑能力，继续沿用原有模板和按钮，但支持结构化富文本内容。
- 最低 TelePilot 版本提升到 `0.67.1`。

## 0.1.23（2026-07-18）

- 发奖和申请补发查找用户近期群消息时，将精确搜索失败后的兜底扫描范围从 200 条提升到 5000 条，并接入 TelePilot 0.67.0 的 UserBot 近期消息锚点缓存。
- 匿名管理员继续只使用 Telegram 消息自身的匿名身份与管理员标签；按钮点击者身份不会用于反向建立消息锚点，避免群内通知泄露真实姓名。
- 最低 TelePilot 版本提升到 `0.67.0`，依赖平台修复真实转账规则群被旧配置误识别为模拟测试群的问题。

## 0.1.22（2026-07-17）

- 最低 TelePilot 版本提升到 `0.60.10`，依赖平台完整透传 payout 的 `reply_to_display_name`，使模拟转账通知继续使用插件已解析的管理员标签。
- 新增截图场景回归测试，覆盖历史数据库真实姓名、匿名管理员标签、顶部运气王/倒霉蛋和折叠总名单同时渲染。

## 0.1.21（2026-07-16）

- 最低 TelePilot 版本统一提升到 `0.60.9`，依赖平台完整修复 UserBot 发奖消息、安全身份映射与模拟转账通知之间的竞争窗口，并覆盖 `+金额`、`-金额` 两条出口。
- payout 动作显式清空 `reply_to_username`，只把 TelePilot 安全身份 facade 返回并截断后的公开名交给平台；匿名管理员后续发奖和转账结果不会携带真实用户名。
- 修复 `plugin.json` 与 `manifest.py` 最低平台版本不一致的问题，避免不同安装入口接受到能力不足的 TelePilot 版本。

## 0.1.20（2026-07-16）

- 发奖动作新增 `reply_to_display_name` 安全公开名，使用 TelePilot 解析出的匿名管理员标签并保持未转义原值，供 UserBot 发奖和模拟转账统一复用。
- 匿名管理员的真实按钮姓名不再进入后续转账展示；最低 TelePilot 版本提升到 `0.60.8`，依赖平台通过管理员交互 Bot 官方核验 `is_anonymous` 与 `custom_title`。

## 0.1.19（2026-07-16）

- 版本 5 的旧账号级重置标记升级时直接丢弃，不再根据历史答题记录推测并复制到多个群；迁移仍保持事务原子性。
- 最低 TelePilot 版本提升到 `0.60.7`，依赖平台插件更新屏障，防止更新期间的旧 worker 实例继续处理命令、交互与定时任务。

- `airp reset` 和 `airp reset all` 改为只重置命令所在群的当日限制，不再影响同一账号管理的其他群；响应和使用说明明确标注“本群”。
- SQLite schema 升级到版本 6，重置记录新增 `chat_id`；旧账号级重置记录会按已有答题记录原子迁移到对应群，升级中断会完整回滚，既有红包、奖励和答题历史不变。

- 结算名单和周榜改为优先显示 Telegram 姓名，姓名为空时才回退到 `@用户名`，展示长度仍最多 10 个字符。

## 0.1.10（2026-07-14）

## 0.1.9（2026-07-14）

- AI 输出改用每行一题的 JSONL；即使最后一行因模型输出上限被截断，前面已完成的题目仍可校验、保存并在后续仅补齐缺口。
- 单批输入同样遵守 12 万字符上限；超长网页按首段、中段和尾段抽样，避免一次请求吞入完整 30 万字符正文。

## 0.1.7（2026-07-14）

- 题库生成支持中断、终止和继续：每个成功批次立即保存阶段性题库，中断、Provider 失败或服务重启后不再丢失已生成题目。
- 再次生成会复用缓存正文和阶段性题库，并读取配置页当前选择的 Provider 与模型，支持切换模型后继续补齐。
- 支持流式接收 AI 输出，并在任务窗口节流展示当前批次已接收字符数；不支持流式的 Provider 自动回退普通生成。
- AI 调用异常纳入有限重试；批次失败时记录具体错误摘要并自动降低后续并发，减少限流和超时造成的连续失败。
- 新增“自动置顶红包入口”配置，默认由交互 Bot 置顶带领取按钮的红包消息，避免群聊后续发言淹没入口。
- 红包开场提供“领取我的雨露”按钮，每道题和答题结果提供“我也要雨露均沾”按钮，所有群成员可随时加入；题面会以“@用户名 这是你的专属雨露”标记归属，答案按钮继续严格绑定本人。
- 最低 TelePilot 版本调整为 0.59.0，以使用后台配置任务中断与终止控制。

- 新增 `{date}` 通用模板占位符，按配置时区输出 `YYYY-MM-DD`；默认红包开场模板会自动展示今日日期。

## 0.1.2（2026-07-14）

- 题库首次生成改为单次按钮触发、内部自动分批调用 AI，每批限制输出规模，避免一次生成大量题目时返回超长或损坏 JSON。
- 每批 AI 结果都会进行严格 JSON 与题目结构校验，格式损坏时自动重试；所有批次完成后才一次性保存，失败时不会留下不完整题库。
- 配置动作日志新增分批重试和已生成题数进度，方便直接判断网页抓取、AI 调用与题库保存分别进行到哪一步。
